# Defect Report: D-11

## Stateless JWT tokens remain active and valid following password modification and logout

| Property | Value |
|---|---|
| **Defect ID** | `D-11` |
| **Module** | M1 Auth & M4 Profile |
| **Severity** | **High** |
| **Priority** | `P1` |
| **CWE Classification** | CWE-613: Insufficient Session Expiration |
| **Triggering Test Cases** | `TC-USR-010`, `TC-SEC-012` |
| **SUT Target Commit** | `ecd4de475fdf49d54153ffaa57d42b392161007a` |

### 1. Description
JWT tokens are issued purely stateless without server-side invalidation, token version tracking (`tokenVersion`), or revocation lists. When a user changes their password or clicks "Log Out", previously captured tokens remain fully valid until their 24-hour expiration timestamp expires.

### 2. Root Cause Analysis
Stateless token issuance without `tokenVersion` counter in User model checked during `secureRoute`.

### 3. Expected vs Actual Result
- **Expected**: HTTP 401 Unauthorized when presenting tokens issued prior to password change or logout.
- **Actual**: HTTP 200 OK — prior tokens retain full API and WebSocket access.

### 4. Reproduction Steps
1. Navigate to test suite `05_Test_Automation/`.
2. Execute corresponding automated test: `npx vitest run --filter "TC-USR-010"`.
3. Observe honest test failure confirming defect behavior.

### 5. Recommended Remediation
Add `tokenVersion: { type: Number, default: 0 }` to User model; increment on password change/logout and embed version in JWT payload.
