# Defect Report: D-14

## Inconsistency between Cookie Max-Age (7 days) and JWT Expiration (1 day)

| Property | Value |
|---|---|
| **Defect ID** | `D-14` |
| **Module** | M1 Authentication |
| **Severity** | **Low** |
| **Priority** | `P3` |
| **CWE Classification** | CWE-1068: Inconsistency Between Implementation and Documented Design |
| **Triggering Test Cases** | `TC-AUTH-025` |
| **SUT Target Commit** | `ecd4de475fdf49d54153ffaa57d42b392161007a` |

### 1. Description
In `auth.controller.js:29`, the cookie is set with `maxAge: 7 * 24 * 60 * 60 * 1000` (7 days), while the embedded JWT token is signed with `expiresIn: "1d"` (24 hours). For days 2 through 7, the client transmits an expired token causing unexpected 401 errors while the browser considers the session cookie still fresh.

### 2. Root Cause Analysis
Mismatched expiration constants in `utils/jwt.js` and `controllers/auth.controller.js`.

### 3. Expected vs Actual Result
- **Expected**: Cookie Max-Age matches token lifetime exactly (86400000 ms).
- **Actual**: Cookie survives 6 days past token validity.

### 4. Reproduction Steps
1. Navigate to test suite `05_Test_Automation/`.
2. Execute corresponding automated test: `npx vitest run --filter "TC-AUTH-025"`.
3. Observe honest test failure confirming defect behavior.

### 5. Recommended Remediation
Harmonize expiration constants using `env.jwt_expires_in`.
