# Defect Report: D-04b

## User signup duplicate detection is case-sensitive, permitting duplicate account collision

| Property | Value |
|---|---|
| **Defect ID** | `D-04b` |
| **Module** | M1 Authentication |
| **Severity** | **High** |
| **Priority** | `P2` |
| **CWE Classification** | CWE-178: Improper Handling of Case Sensitivity |
| **Triggering Test Cases** | `TC-AUTH-015`, `TC-EP-006` |
| **SUT Target Commit** | `ecd4de475fdf49d54153ffaa57d42b392161007a` |

### 1. Description
`handleUserSignup` queries `User.findOne({ email })` using the raw casing supplied by the client without normalizing to lowercase. Consequently, `alice@example.com` and `ALICE@EXAMPLE.COM` are treated as distinct entities, allowing account spoofing and duplicate registration.

### 2. Root Cause Analysis
Querying without `.toLowerCase()` normalization before checking database uniqueness.

### 3. Expected vs Actual Result
- **Expected**: HTTP 400 Bad Request: `{"message": "User already exists"}`.
- **Actual**: HTTP 201 Created — second account created with uppercase email.

### 4. Reproduction Steps
1. Navigate to test suite `05_Test_Automation/`.
2. Execute corresponding automated test: `npx vitest run --filter "TC-AUTH-015"`.
3. Observe honest test failure confirming defect behavior.

### 5. Recommended Remediation
Always normalize email via `email.toLowerCase().trim()` before database queries and user creation.
