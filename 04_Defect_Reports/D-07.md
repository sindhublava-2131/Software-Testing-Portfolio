# Defect Report: D-07

## Admin users pagination with negative page or limit triggers unhandled MongoDB BSON error 500

| Property | Value |
|---|---|
| **Defect ID** | `D-07` |
| **Module** | M5 Administration |
| **Severity** | **Medium** |
| **Priority** | `P2` |
| **CWE Classification** | CWE-1284: Improper Input Validation |
| **Triggering Test Cases** | `TC-ADM-010`, `TC-BVA-019` |
| **SUT Target Commit** | `ecd4de475fdf49d54153ffaa57d42b392161007a` |

### 1. Description
In `getAllUsers` (`admin.controller.js`), the skip calculation `const skip = (page - 1) * limit` does not clamp `page` or `limit` with `Math.max(1, ...)`. Passing `page=-1` produces `skip = -20`. When passed to Mongoose `skip(-20)`, MongoDB throws BSON error 51024 (`BSON field 'skip' value must be >= 0, actual value '-20'`), resulting in an unhandled 500 crash.

### 2. Root Cause Analysis
Missing bounds checking on query parameters: `const page = Math.max(1, parseInt(req.query.page) || 1)`.

### 3. Expected vs Actual Result
- **Expected**: HTTP 400 Bad Request or clamped to page 1.
- **Actual**: HTTP 500 Internal Server Error with MongoServerError: Location51024.

### 4. Reproduction Steps
1. Navigate to test suite `05_Test_Automation/`.
2. Execute corresponding automated test: `npx vitest run --filter "TC-ADM-010"`.
3. Observe honest test failure confirming defect behavior.

### 5. Recommended Remediation
Sanitize query pagination with `const page = Math.max(1, parseInt(req.query.page) || 1); const limit = Math.max(1, Math.min(50, parseInt(req.query.limit) || 10));`.
