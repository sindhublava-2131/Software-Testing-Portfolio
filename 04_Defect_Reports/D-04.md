# Defect Report: D-04

## Signup validation failure returns HTTP 500 Internal Server Error instead of HTTP 400

| Property | Value |
|---|---|
| **Defect ID** | `D-04` |
| **Module** | M1 Authentication |
| **Severity** | **Medium** |
| **Priority** | `P2` |
| **CWE Classification** | CWE-388: Error Handling |
| **Triggering Test Cases** | `TC-AUTH-014`, `TC-EP-005` |
| **SUT Target Commit** | `ecd4de475fdf49d54153ffaa57d42b392161007a` |

### 1. Description
When invalid input (such as an invalid email string "alice_at_example_dot_com") fails Mongoose schema validation (`User.create(...)`), the thrown `ValidationError` is caught by the generic catch block in `handleUserSignup`, which responds with `res.status(500).json(...)` rather than recognizing it as a client input validation fault (HTTP 400).

### 2. Root Cause Analysis
Absence of `if (error.name === "ValidationError") return res.status(400)...` error type classification in `auth.controller.js`.

### 3. Expected vs Actual Result
- **Expected**: HTTP 400 Bad Request with specific validation error messages.
- **Actual**: HTTP 500 Internal Server Error: `{"message": "Something went wrong from server"}`.

### 4. Reproduction Steps
1. Navigate to test suite `05_Test_Automation/`.
2. Execute corresponding automated test: `npx vitest run --filter "TC-AUTH-014"`.
3. Observe honest test failure confirming defect behavior.

### 5. Recommended Remediation
Inspect `error.name` or `error.errors` in catch blocks and return HTTP 400 for validation errors.
