# Defect Report: D-06

## MyBids listing does not resolve winning status on expired auctions unless individual page is visited

| Property | Value |
|---|---|
| **Defect ID** | `D-06` |
| **Module** | M2 Auction Management |
| **Severity** | **Medium** |
| **Priority** | `P3` |
| **CWE Classification** | CWE-840: Business Logic Errors |
| **Triggering Test Cases** | `TC-E2E-024`, `TC-ST-006` |
| **SUT Target Commit** | `ecd4de475fdf49d54153ffaa57d42b392161007a` |

### 1. Description
The winner resolution logic (`auction.winner = highestBidder._id; auction.isSold = true; await auction.save();`) only resides inside `auctionById` (GET /api/auction/:id). If an auction expires and a bidder checks GET /api/auction/mybids or the MyBids frontend page without visiting the individual auction detail URL, the database record remains un-finalized (`winner: null, isSold: false`).

### 2. Root Cause Analysis
Absence of scheduled cron finalization job or unified expiration resolution middleware.

### 3. Expected vs Actual Result
- **Expected**: Expired auctions in MyBids automatically reflect winning status and winner identity.
- **Actual**: Auction displays unfinalized/pending status until an individual GET /:id request triggers resolution.

### 4. Reproduction Steps
1. Navigate to test suite `05_Test_Automation/`.
2. Execute corresponding automated test: `npx vitest run --filter "TC-E2E-024"`.
3. Observe honest test failure confirming defect behavior.

### 5. Recommended Remediation
Implement background cron job or hook in `myBids` query that resolves winners on all expired items.
