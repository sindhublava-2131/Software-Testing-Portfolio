# Defect Report: D-05b

## Upload session formId replay vulnerability permits duplicate auction instantiation

| Property | Value |
|---|---|
| **Defect ID** | `D-05b` |
| **Module** | M2 Auction Management |
| **Severity** | **High** |
| **Priority** | `P1` |
| **CWE Classification** | CWE-294: Authentication Bypass by Capture-replay |
| **Triggering Test Cases** | `TC-AUC-007`, `TC-ST-008` |
| **SUT Target Commit** | `ecd4de475fdf49d54153ffaa57d42b392161007a` |

### 1. Description
`createAuction` verifies `Upload.findOne({ formId })`. Although it marks `upload.status = "used"` upon successful creation, the query does not check `{ formId, status: "pending" }`. A compromised or replayed payload with an already-used formId succeeds in creating duplicate auction entries.

### 2. Root Cause Analysis
`Upload.findOne({ formId })` instead of `Upload.findOne({ formId, status: "pending" })`.

### 3. Expected vs Actual Result
- **Expected**: HTTP 400 Bad Request: `{"message": "Upload session has already been consumed"}`.
- **Actual**: HTTP 201 Created — duplicate auction generated.

### 4. Reproduction Steps
1. Navigate to test suite `05_Test_Automation/`.
2. Execute corresponding automated test: `npx vitest run --filter "TC-AUC-007"`.
3. Observe honest test failure confirming defect behavior.

### 5. Recommended Remediation
Change query to `await Upload.findOneAndUpdate({ formId, status: "pending" }, { status: "used" })`.
