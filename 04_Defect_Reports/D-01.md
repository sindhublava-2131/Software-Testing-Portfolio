# Defect Report: D-01

## Bidding permitted on future auctions before itemStartDate has elapsed

| Property | Value |
|---|---|
| **Defect ID** | `D-01` |
| **Module** | M3 Live Bidding |
| **Severity** | **Critical** |
| **Priority** | `P1` |
| **CWE Classification** | CWE-840: Business Logic Errors |
| **Triggering Test Cases** | `TC-BID-020`, `TC-BVA-012`, `TC-ST-004` |
| **SUT Target Commit** | `ecd4de475fdf49d54153ffaa57d42b392161007a` |

### 1. Description
The `placeBid` controller in `auction.controller.js` validates that an auction has not expired (`new Date(product.itemEndDate) < new Date()`), but completely omits checking whether the auction has actually started (`new Date(product.itemStartDate) > new Date()`). Consequently, bidders can discover and place bids on future scheduled auctions before their official opening time.

### 2. Root Cause Analysis
Missing validation condition: `if (new Date(product.itemStartDate) > new Date()) return res.status(400).json({ message: "Auction has not started yet" });` in `controllers/auction.controller.js:187`.

### 3. Expected vs Actual Result
- **Expected**: HTTP 400 Bad Request with message "Auction has not started yet".
- **Actual**: HTTP 200 OK — bid accepted and price incremented.

### 4. Reproduction Steps
1. Navigate to test suite `05_Test_Automation/`.
2. Execute corresponding automated test: `npx vitest run --filter "TC-BID-020"`.
3. Observe honest test failure confirming defect behavior.

### 5. Recommended Remediation
Add guard check `if (new Date(product.itemStartDate) > new Date()) return res.status(400).json({ message: "Auction has not started yet" });` in both `controllers/auction.controller.js` and `socket/auction.handler.js`.
