# Defect Report: D-10

## NoSQL operator injection vulnerability in login authentication query

| Property | Value |
|---|---|
| **Defect ID** | `D-10` |
| **Module** | M1 Authentication |
| **Severity** | **High** |
| **Priority** | `P1` |
| **CWE Classification** | CWE-943: Improper Neutralization of Special Elements in Data Query Logic |
| **Triggering Test Cases** | `TC-SEC-005`, `TC-AUTH-019` |
| **SUT Target Commit** | `ecd4de475fdf49d54153ffaa57d42b392161007a` |

### 1. Description
In `handleUserLogin`, the email parameter is extracted directly from `req.body` and passed into `User.findOne({ email })`. When a JSON payload containing a MongoDB query operator (`{"email": {"$gt": ""}, "password": "..."}`) is supplied, Mongoose evaluates the operator query rather than matching a literal string. If the password matches the first returned record, an attacker logs in without knowing the victim's email.

### 2. Root Cause Analysis
Absence of input type assertion or query sanitization (`express-mongo-sanitize`).

### 3. Expected vs Actual Result
- **Expected**: HTTP 400 Bad Request: `{"message": "Invalid email parameter"}`.
- **Actual**: Query executes with operator; if operator matches, proceeds to password evaluation.

### 4. Reproduction Steps
1. Navigate to test suite `05_Test_Automation/`.
2. Execute corresponding automated test: `npx vitest run --filter "TC-SEC-005"`.
3. Observe honest test failure confirming defect behavior.

### 5. Recommended Remediation
Enforce type validation: `if (typeof email !== "string") return res.status(400)...` or install `express-mongo-sanitize`.
