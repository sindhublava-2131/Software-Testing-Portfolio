# Defect Report: D-08

## Absence of rate limiting across authentication and public contact endpoints

| Property | Value |
|---|---|
| **Defect ID** | `D-08` |
| **Module** | M1 Auth & M6 Contact |
| **Severity** | **High** |
| **Priority** | `P1` |
| **CWE Classification** | CWE-799: Improper Control of Generation of Code or Resource Consumption |
| **Triggering Test Cases** | `TC-CNT-008`, `TC-SEC-011` |
| **SUT Target Commit** | `ecd4de475fdf49d54153ffaa57d42b392161007a` |

### 1. Description
Neither `express-rate-limit` nor any throttling mechanism is implemented on POST /api/contact or POST /api/auth/login. An automated script can execute thousands of requests per minute, allowing brute-force password cracking and third-party email quota exhaustion (Resend API flooding).

### 2. Root Cause Analysis
No rate limiting middleware configured in Express application pipeline.

### 3. Expected vs Actual Result
- **Expected**: HTTP 429 Too Many Requests after threshold (e.g. 5 attempts / 15 minutes).
- **Actual**: All rapid requests return HTTP 200/401 with no throttling.

### 4. Reproduction Steps
1. Navigate to test suite `05_Test_Automation/`.
2. Execute corresponding automated test: `npx vitest run --filter "TC-CNT-008"`.
3. Observe honest test failure confirming defect behavior.

### 5. Recommended Remediation
Install and configure `express-rate-limit` on `/api/auth/login` and `/api/contact`.
