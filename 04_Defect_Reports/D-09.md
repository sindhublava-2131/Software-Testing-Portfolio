# Defect Report: D-09

## Validation order divergence between REST API and Socket.IO for expired seller bidding

| Property | Value |
|---|---|
| **Defect ID** | `D-09` |
| **Module** | M3 Live Bidding |
| **Severity** | **Low** |
| **Priority** | `P3` |
| **CWE Classification** | CWE-698: Execution After Redirect (Order of Precedence) |
| **Triggering Test Cases** | `TC-DT-008`, `TC-SOC-014` |
| **SUT Target Commit** | `ecd4de475fdf49d54153ffaa57d42b392161007a` |

### 1. Description
When a seller attempts to bid on their own expired auction: REST `placeBid` checks seller identity FIRST (`if (product.seller.toString() === user) return 403`), whereas Socket.IO `auction:bid` checks expiration FIRST (`if (new Date(product.itemEndDate) < new Date()) return auction:error ("Auction has already ended")`). This order divergence violates state machine consistency across transport layers.

### 2. Root Cause Analysis
Inconsistent conditional sequencing between `controllers/auction.controller.js:181-188` and `socket/auction.handler.js:58-70`.

### 3. Expected vs Actual Result
- **Expected**: Uniform error status/event precedence regardless of transport channel.
- **Actual**: REST responds with 403 (Forbidden Seller), while Socket emits "Auction has already ended".

### 4. Reproduction Steps
1. Navigate to test suite `05_Test_Automation/`.
2. Execute corresponding automated test: `npx vitest run --filter "TC-DT-008"`.
3. Observe honest test failure confirming defect behavior.

### 5. Recommended Remediation
Standardize validation order across REST controllers and WebSocket handlers.
