# Defect Report: D-05

## Auction creation with invalid parameters returns HTTP 500 instead of HTTP 400

| Property | Value |
|---|---|
| **Defect ID** | `D-05` |
| **Module** | M2 Auction Management |
| **Severity** | **Medium** |
| **Priority** | `P2` |
| **CWE Classification** | CWE-388: Error Handling |
| **Triggering Test Cases** | `TC-AUC-008`, `TC-AUC-009`, `TC-AUC-011`, `TC-AUC-012`, `TC-AUC-013`, `TC-AUC-014`, `TC-BVA-007`, `TC-EP-015` |
| **SUT Target Commit** | `ecd4de475fdf49d54153ffaa57d42b392161007a` |

### 1. Description
In `createAuction`, boundary failures (startingPrice: 0, negative prices, missing itemName or category) pass through controller pre-checks and fail Mongoose schema validation, where the resulting exception is caught and returned as HTTP 500.

### 2. Root Cause Analysis
Controller relies on Mongoose schema for required field enforcement and catches all failures as 500 in `auction.controller.js:67`.

### 3. Expected vs Actual Result
- **Expected**: HTTP 400 Bad Request with descriptive validation details.
- **Actual**: HTTP 500 Internal Server Error: `{"message": "Error creating auction", "error": "..."}`.

### 4. Reproduction Steps
1. Navigate to test suite `05_Test_Automation/`.
2. Execute corresponding automated test: `npx vitest run --filter "TC-AUC-008"`.
3. Observe honest test failure confirming defect behavior.

### 5. Recommended Remediation
Add Joi/Zod or manual pre-validation in controller returning HTTP 400 for input boundary violations.
